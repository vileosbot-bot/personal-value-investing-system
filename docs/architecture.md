# 架构

## 设计原则

- 先保证证据、判断、计算和复盘能串成最小闭环，再增加数据平台。
- 计算确定、输入显式、缺失失败，不静默补数。
- 当前事实与历史时点事实分开；研究输入与后续结果分开。
- 用户判断区与智能体分析区分开；冻结记录不可原地覆盖。

## 模块

1. **证据层**：记录来源、资料截止日、公开可用日、口径和原始哈希。
2. **研究层**：公司怎样赚钱、护城河、管理层、资本配置、财务质量和行业空间。
3. **模型路由层**：按公司经济特征选择主模型和交叉检查模型。
4. **计算层**：情景、现金流、估值、市场隐含预期、五年预期收益和敏感性。
5. **决策层**：用户临时判断、反方论证、冻结决策卡和替代关系。
6. **验证层**：历史时点隔离、股东总回报、最大回撤、基准和归因。
7. **报告层**：初学者简版与可审计详版，共享同一输入和结果哈希。

## 当前实现

当前使用 Markdown、JSON 和 Python 标准库：

- Markdown 承载需求、研究与冻结记录；
- JSON 承载可验证的示例和未来模型输入；
- Python 提供确定性计算；
- JSON 冻结 V1.1 模型与历史复演 V1.0 的回归输入和预期结果；
- 单元测试保护公式和边界。

计算层已覆盖增长折现、价值驱动企业自由现金流、银行剩余收益、五年预期收益和反向求解；验证层已覆盖 A 区冻结校验、分红再投资、拆并股和 B 区误差归因。

当前不使用数据库，也不自动联网抓取。这样可以先验证流程、字段和公式，避免在需求未稳定时把复杂度固化到基础设施。

## 未来升级门

进入自动数据和存储阶段前，必须明确：数据授权、时点可得性、原始文件保留、版本与修订、身份与证券映射、公司行动、人工审核和隐私边界。数据库只能服务这些已确认契约，不能替代契约本身。
